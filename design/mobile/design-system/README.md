MyAstroSky overlays astrophotographs on an interactive sky map (HTML5 canvas, stereographic polar projection) and recommends deep-sky targets from the user's gear, location and sky conditions. It is a dense, dark, technical instrument: build screens that stay out of the way of the sky. Everything below is stated for an agent that will build screens with this system.

Load `tokens.css`, then `components/bundle.css`, and set `data-theme` on `<html>` to a theme id (`cold-blue-v2`, `cold-blue`, `warm` or `night-red`); `cold-blue-v2` is the fallback and the app's default. Components are plain classes on plain elements (no JavaScript bundle); each folder in `components/` has a preview and its rules. Components in "Mobile — proposed" are new and are not in the code.

## Content fundamentals

- The UI is written in four languages: French (`fr`), English (`en`), Spanish (`es`) and German (`de`). **French is the default**: the language is read from `localStorage['lang']`, then from `navigator.languages`, and falls back to `fr`. Write every user-facing string as `t('section.key')` with an entry in all four files `src/i18n/{fr,en,es,de}.ts` (server messages live in `server/messages.ts`). Never hard-code a visible string in a component.
- Constellation and DSO names come from `displayName`, which is filled per language at load time; do not translate catalogue ids (M31, NGC 7000, HIP 91262).
- Tone: plain, technical and short, like an instrument panel. Buttons are verbs ("Supprimer", "Annuler", "Trouver des cibles"); statuses are an action in progress with an ellipsis ("Résolution en cours…") or a result with a check and a dash ("✓ Résolu en 12s — prêt à placer"). Sentence case, no exclamation marks, no emoji, no marketing voice.
- Typography of copy: French uses a space before `?`, `:` and inside guillemets (« {name} »); English uses straight quotes; Spanish opens questions with `¿`; the ellipsis is the single character `…`. Placeholders are `{name}`, `{count}`, `{seconds}`.
- Real strings, as the app writes them:

| Key                           | fr                                                                            | en                                                                        |
| ----------------------------- | ----------------------------------------------------------------------------- | ------------------------------------------------------------------------- |
| `app.loading`                 | Chargement du catalogue stellaire…                                            | Loading star catalog…                                                     |
| `photos.add`                  | + Ajouter des photos                                                          | + Add photos                                                              |
| `search.placeholder`          | Rechercher étoile ou DSO…                                                     | Search star or DSO…                                                       |
| `photos.deleteConfirmTitle`   | Supprimer cette photo ?                                                       | Delete this photo?                                                        |
| `photos.deleteConfirmMessage` | « {name} » et toutes les données associées seront supprimées définitivement.  | "{name}" and all associated data will be permanently deleted.             |
| `targets.plan.noPlans`        | Aucun plan pour l'instant                                                     | No plans yet                                                              |
| `targets.plan.empty`          | Aucune cible dans ce plan. Ajoutez-en depuis les suggestions ou la recherche. | No targets in this plan yet. Add some from the recommendations or search. |
| `modal.solvedOnline`          | ✓ Résolu en {seconds}s — prêt à placer                                        | ✓ Solved in {seconds}s — ready to place on map                            |

The same key in the other two languages: `photos.add` is "+ Añadir fotos" (es) and "+ Fotos hinzufügen" (de); `photos.deleteConfirmTitle` is "¿Eliminar esta foto?" and "Dieses Foto löschen?". Texts must fit in the longest of the four languages.

## Visual foundations

**Never hard-code a colour or a pixel value.** Every colour, space, radius, size and stacking value is a token (`var(--bg-card)`, `var(--space-4)`, `var(--radius-md)`, `var(--z-modal)`); a value that is truly off the scale becomes a new token first. Shadow tokens are colours: write the geometry in the rule (`0 4px 20px var(--shadow-md)`).

**Surfaces, from the page outward.**

- Page: `bg-app`. Side panel and floating control clusters: `bg-panel`. Modals, dialogs, toasts and the sky tooltip: `bg-deep`. Anchored popovers and the click tooltip: `bg-modal`. Dropdown lists: `bg-dropdown`. Dimmed backdrops: `bg-overlay` (`bg-overlay-heavy` for full-screen viewers).
- Cards: `bg-card` with a `border-panel` border. Inputs, selects and textareas: `bg-input` with `border-input`. Inline data panels and suggestion lists: `bg-surface`. Hovered rows: `bg-hover`.
- Dividers: `border-subtle` between list items, `border-chrome` for structural chrome, the `border-white-xs` to `border-white-xl` ramp for neutral borders of increasing strength (`border-white-md` is the resting border of icon buttons).

**Text levels.** Name the level, not a colour. `text-bright`: highlighted names, DSO names, active icons and the label of an amber button. `text-primary`: body text and input values. `text-secondary`: photo names, tooltip text, second lines. `text-label`: section headers, checkbox and slider labels. `text-dim`: instructions, placeholders and hints. `text-muted`: pagination info and form hints, the weakest level, never the only carrier of meaning. `text-hint`: empty states. Never use a raw hex for text.

**Accent.** One accent hue per theme (steel blue in `cold-blue-v2`, amber in `warm`). Choose its strength by role: `accent-bg` for a primary fill (and the selected icon button), `accent-bg-hover` for its hover, the `accent-fill-sm` / `-md` / `-lg` / `-xl` / `-2xl` ramp (12, 20, 35, 50, 60 %) for tints and washes, `border-accent` and `border-focus` for outlines, `accent-color` for native checkboxes and ranges. Confirm is green (`btn-confirm-*`), destructive is red (`btn-danger-*`, `color-danger`); these two are the same in every real theme.

**States.** One scale for every icon-only button: the fill rises 0, 35, 55, 75 % over rest, hover (`accent-fill-lg`), selected (`accent-bg`), selected hover (`accent-bg-hover`); a hover must never look more "on" than a selected button, and "off" is never drawn with reduced opacity. Disabled is opacity .5 on `btn-action`, .4 on the other buttons, .35 on floating map buttons. Keyboard focus is a 2px solid `spinner-active` outline with a 2px offset (inputs also change `border-focus`). Status is a token trio per state (`status-success-*`, `status-error-*`, `status-info-*`, `status-warn-*`: bg, border, text) and always carries a word or a glyph, never colour alone. Filter chips have a fixed colour per filter (`filter-ha`, `filter-oiii`, …) and look identical everywhere.

**Spacing.** The `space-*` scale moves in 2px steps from `space-1` (2px) to `space-9` (24px), with half-steps (`space-1h` 3px …) and large steps up to `space-21` (100px). Standard gap `space-4` (8px); modal padding `space-7` (16px); panel padding `space-8` (20px); the side panel is `panel-width` (280px). Mobile spacing sits on the 8px grid (`mobile-grid`).

**Radii.** `radius-xs` 2px for chips, `radius-sm` 4px for inputs and icon buttons, `radius-md` 6px for text buttons and cards, `radius-lg` 8px for floating map buttons, toasts and popups, `radius-xl` 10px for modals and target cards, `radius-pill` for circular controls. No large rounded cards on desktop.

**Z-index.** `z-base` 1, `z-panel` 10, `z-toggle` 11, `z-sidebar` 20, `z-modal` 200, `z-meta` 210, `z-gallery` 220, `z-tooltip` 10000. Use the token, never a literal.

**Type.** Three families. `sans` (Outfit) for all UI text. `mono` (DM Mono) for coordinates, catalogue values, chips and search inputs. `display` (Cormorant Garamond) for panel headings, collapsible section headers and gallery titles. UI sizes are small and dense: 12px to 13px for body, 11px for chips and metadata, 10px for uppercase micro labels, 16px to 18px for headers (the `ui-*` styles). Section headers are 13px, 600, 0.05em tracking, uppercase. The fonts are Google-hosted (`index.html`), so `type.fonts` is empty; offline they fall back to Georgia, Consolas and the system UI font.

**Elevation, motion, imagery.** Surfaces are flat with 1px borders; shadows appear only on floating things (dialog, popups, toolbar) and use `shadow-md` to `shadow-lg`. Blur is used on the side panel and floating clusters (4 to 12px). Transitions are short (0.14 to 0.3s, ease or linear for spinners); nothing bounces. Imagery is the user's own astrophotographs shown on the map; the only brand picture is the raster logo in `assets/Logos`. No decorative gradients; the sky background gradient belongs to the canvas.

## The sky canvas

The map look is **fixed and independent of the UI theme**: it comes from `SKY_THEME` in `src/sky-themes.ts` and `src/canvas-theme.ts`, so the sky is the same in all four themes. Do not re-tint it and do not use `sky-bg-inner`, `sky-bg-outer` or `constellation-line` (defined, read by nothing). Canvas text is the system `sans-serif`, 9 to 11px.

| Layer                          | Value                                                                                                                     |
| ------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| Base fill                      | `#040810`, always opaque                                                                                                  |
| Background gradient            | radial, `rgba(26, 38, 66, 0.55)` at the centre to `rgba(3, 5, 12, 0.6)` at the far corner, vignette `rgba(1, 2, 6, 0.55)` |
| RA/Dec grid / equator / labels | `rgba(90, 130, 200, 0.35)` / `rgba(120, 165, 235, 0.65)` / `rgba(155, 190, 240, 0.9)`                                     |
| Constellation lines / names    | `rgba(140, 165, 220, 0.5)` / `rgba(185, 170, 155, 0.4)`                                                                   |
| Star labels                    | `rgba(195, 180, 160, 0.55)`                                                                                               |
| Azimuth grid / labels          | `rgba(110, 200, 140, 0.35)` / `rgba(150, 220, 175, 0.85)`                                                                 |
| Moon (lit, shadow, outline)    | `rgba(225, 230, 245, 0.92)`, `rgba(30, 34, 48, 0.9)`, `rgba(190, 195, 215, 0.7)`                                          |
| Sun, Mars, Neptune             | `rgba(255, 214, 120, 0.95)`, `rgba(225, 120, 85, 0.95)`, `rgba(95, 130, 230, 0.95)`                                       |
| Stars                          | blue-white to orange from B-V, pulled 45 % toward white; bright stars get a coloured halo                                 |

DSO markers are semantic and keep their own hues: galaxies amber, emission nebulae red, planetary nebulae cyan, supernova remnants green, open clusters dashed cream. Four overlays do read the theme or the tokens: the horizon line and the active FOV frame use `accent-color`, FOV frames use `fov-frame-stroke` and `fov-frame-label`, and the N/E/S/W letters are `cardinal-point` (`#ff4d4d`, the same red in every theme). Photos placed on the map are the user's pixels; never tint them.

## Iconography

Two tiers, never mixed for one meaning. Tier 1: the 48 SVG files in `assets/Icons` (single-ink, `currentColor`, no width or height). Inline the markup, size it with CSS and let the button's `color` recolour it; an `<img>` cannot inherit colour. Tier 2: Unicode text glyphs for simple affordances, assigned as text: `×` close or dismiss, `⚙` settings, `↺` `↻` rotate, `◎` reset rotation, `▾` expand, `▶` `◀` panel toggle, `⠿` drag handle, `−` `+` zoom, `⟲` reset zoom, `✓` success, `⚠` warning, `i` info. Do not add a new Unicode glyph or SVG without listing it. A trash can in the danger colour marks every per-item delete; a plain cross is only for dismiss and close. Ratings use `★` `☆`, difficulty uses `◆` `◇`. The logo is the raster `assets/Logos/icon.png`; there is no vector mark.

## Themes

| Theme id       | Name                   | Use                                                                                                                                                           |
| -------------- | ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `cold-blue-v2` | Cold blue v2 — default | Deep space navy with a steel-blue accent, inspired by dark FITS viewers and Stellarium's night mode. The default theme of the app ("Froid moderne (défaut)"). |
| `cold-blue`    | Cold blue              | Classic cold: navy blacks with an electric-blue accent, reconstructed from the app's pre-amber era.                                                           |
| `warm`         | Warm amber             | Amber on near-void black; the bare `:root` of the code.                                                                                                       |
| `night-red`    | Night red — proposed   | For use in the field, to protect dark adaptation. **Proposed and not yet in the code.**                                                                       |

Every colour token has an explicit value in all four themes. In the code, each real theme overrides a subset of tokens and inherits the rest from the warm `:root`; status, button, chip and filter colours are shared. `night-red` is computed, not designed: for each token take its `cold-blue-v2` colour, compute its WCAG relative luminance Y, encode it to sRGB as g, and write `rgba(R, 0, 0, a)` (or `#RR0000`) with R = round(255 × min(1, 1.15 g)); aliases stay aliases. The result has a red channel only and keeps the brightness order of the blue theme, but it cannot carry colour meaning: success, error and the filter chips collapse into shades of red, so they must keep their glyph or word. Shipping it needs a `[data-theme='night-red']` block, a picker entry and a check of the canvas.

## The mobile layer

Proposed for the mobile app; not in the code. Everything here is built from tokens and marked "Proposed" in its README.

- **Touch targets.** Every tappable element is at least `mobile-touch-min` (48px) tall and wide; primary controls and list rows use `mobile-touch-comfortable` (56px). Leave at least `mobile-grid` (8px) between two targets. The desktop buttons (about 30px to 41px) are too small: use `.mob-icon-btn`, `mob-seg-btn` and `mob-row`.
- **Text.** Body text and every input are at least 16px (the Mobile type styles `m-body`, `m-body-strong`; `m-title` 20px and `m-large-title` 24px for titles; `m-secondary` 14px, `m-caption` 12px and `m-mono` 14px for support text). Nothing below 12px.
- **Layout.** Screen gutters are `mobile-gutter` (16px) and spacing is a multiple of `mobile-grid` (8px). Navigation is a bottom `TabBar` (Sky, Library, Targets, Plans, Settings, `mobile-tabbar-height`) with a `TopBar` per screen; summoned content is a `BottomSheet` (peek, half, full), not a modal or a side panel; the one creation action is a `FAB`; lists are `ListRow`s; a short exclusive choice is a `SegmentedControl`. Radii: `mobile-sheet-radius` (16px) for sheets, `mobile-card-radius` (12px) for cards and fields.
- **Safe areas.** Pad the top bar with `env(safe-area-inset-top)` and the tab bar and sheets with `env(safe-area-inset-bottom)`, and set `viewport-fit=cover`. Never place a control under a system bar.
- **No hover.** No information or action may exist only on hover: a value shown in a desktop hover tooltip becomes visible text in the row or sheet; pressed states replace hover states; there are no `title` tooltips.
- **No keyboard shortcuts.** The desktop shortcuts are dropped on mobile (decision of 2026-10-03). Where a key was the only way to do something, such as Escape to cancel or close, give the screen a visible control: a close or collapse button of `mobile-touch-min` size.

## Contrast flags

Method: WCAG 2 contrast of every text-colour token against the grounds its usage note names, in every theme. A translucent ground is composited over `bg-app` (for `bg-*` tokens) or over `bg-panel` on `bg-app` (status, button, chip and filter fills); a translucent text colour is composited over its ground. Pairs under 4.5:1 are listed; a source value that misses is kept exact and flagged, not re-tinted. Marks that carry meaning (focus ring, focus border) are held to 3:1. Build screens knowing this: use `text-primary`, `text-bright` and `text-secondary` for anything the user must read, and `text-label`, `text-dim` and `text-muted` only for secondary or non-essential text, as the app does.
