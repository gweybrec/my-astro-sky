# WP3.9 — A storage port, and the last modules that can move to core

Model: sonnet · Branch: `mobile/phase-3b` · Depends on: Phase 3 first part (merged in `dev`) · Needs device: no · Needs browser: no

## Goal

Eleven modules of `src/` hold logic the phone needs but cannot move to `packages/core` because of one browser dependency each (`localStorage`, `navigator`, a DOM helper, a call to `src/api`). Remove each obstacle with the smallest change and move the module (or its pure part) to core, leaving the usual one-line re-export at the old path so that no importer and no test changes. **No behaviour changes.**

## 1. The storage port

`packages/core/src/ports/key-value-store.ts`:

```ts
/** Small texts kept on the device between sessions (the browser's localStorage; the phone's preferences). Synchronous: a platform whose storage is asynchronous loads it in memory at start-up and writes behind. */
export interface KeyValueStore {
  get(key: string): string | null;
  set(key: string, value: string): void;
  remove(key: string): void;
}
```

`packages/core/src/platform/storage.ts`: `configureStorage(store: KeyValueStore): void` and `storage(): KeyValueStore`, with a default in-memory store (as `configureI18n` does for its platform). `src/platform-init.ts` configures it with a store over `localStorage` whose three methods catch exceptions exactly as today's call sites do (a private window can throw): `get` returns `null`, `set` and `remove` do nothing. `tests/setup/platform.ts` already imports `src/platform-init`, so tests keep using happy-dom's `localStorage` and every test that reads or seeds `localStorage` directly keeps working.

Rules for each move (as in Phase 1): `git mv` to `packages/core/src/<same name>.ts`; the old path becomes `export * from '@myastrosky/core/<name>';` (plus `export { default }` when there is one); before moving a module X, search `vi.mock(` for X in `tests/`: when a mocked module is imported by another module **inside core**, the mock no longer intercepts it; change that mock's path to `@myastrosky/core/X` and list it; run `npm run typecheck:core` after each move; if a module does not type-check in core after the change described, revert that module and report it rather than widening the change.

## Must NOT

- Change what is stored (keys, formats) or any default value.
- Edit logic beyond the obstacle's removal.

## Tests

New unit tests for the storage port's default and browser implementations (a throwing `localStorage`), the error hook, `detectInitialDensity(hints)`, the gear loader and the star-search hook. Existing tests unchanged, except mock paths as described.
