# CLAUDE.md — `apps/mobile/`

Auto-loaded under `apps/mobile/`. The phone app: Capacitor (Android) + Ionic Vue, on the shared `@myastrosky/*` packages.

- **Device rule:** never install or launch an emulator, AVD or system image; never run sdkmanager or avdmanager; Gradle must not download SDK packages (`android.builder.sdkDownload=false`). Test on the user's real phone, and put `-s <serial>` on every adb command.
- **No screen without a mockup** (listed in `docs/dev/ui/mobile.md`); build exactly what the mockup shows. The mockups are on the Claude Design page; a local copy of their source, when present, is the untracked `design/mobile/` folder. Texts, descriptions and icons come only from the mockups, never invented.
- **Ionic's components first** (tabs, page, header, content, select, overlays); the look comes from the design system's `.mob-*` classes and tokens, which the app ships in `src/theme/design-system/`. Tokens only, no raw colours or sizes. Ionic's global variables are mapped to the tokens in `src/theme/ionic-tokens.css`, each shared component's own in `src/theme/phone-components.css`, and nowhere else. Dark only.
- **Shared components:** screens use `src/components/Phone*.vue` (button, icon button with long-press name, search, field, row, toggle row, slider row, tick-box row, floating plus, facts, footer, helper line, back button, sheet, chip, badge, empty state, busy, info button, reorder list) and `src/composables/` (`useConfirm`, `useErrorToast`), never a plain `<button>`/`<input>`. Every component in every state is on `/dev/components` (development builds and the alignment check's build only).
- **Sheets:** a sheet is a `PhoneSheet` (Ionic modal) or a `PhoneMapSheet` (over the map, inside a `PhoneMapSheetHost`, which gives it its slide in and out; outside one it throws). Never draw `.mob-sheet` / `.mob-map-sheet` / `.mob-sheet-grab` by hand: `scripts/check-sheets.mjs` (in `npm run verify`) fails on it.
- **Imports:** the shared packages by `@myastrosky/*` names, the desktop's icon SVGs through `@icons/…`; nothing from the repository's `src/` or `server/` (ESLint error). What a screen needs from the desktop moves to a shared package first.
- **Texts** go through `t('…')`; the phone's own keys are in `packages/core/src/i18n/mobile/{fr,en,es,de}.ts`. Reuse an existing key when the text already exists.
- **Safe areas** are `--safe-top/bottom/left/right` (set once in `ionic-tokens.css`; `ion-tabs` and the pushed pages' `ion-page` apply left and right); a screen never reads `env()`.
- **Start-up** is `src/platform-init.ts` (storage, language, backend, hooks), awaited in `src/main.ts` before mounting; a failure shows `StartupError`. `isNativePlatform()` there is the only place that tells the phone from a browser.
- **In a phone-sized browser** (viewport 412 × 915, then 915 × 412): `npm run dev:server` with an isolated `DB_PATH` and `UPLOADS_DIR`, and `npm run mobile:dev` (port 5174; `/api`, `/uploads`, `/data` go to port 3001). The system bars are 0 in a browser: set `--safe-top` and `--safe-bottom` to `24px` on `<html>` to match the boards.
- **On the device:** `npm run mobile:android:build` makes the debug APK (web build, `cap sync android`, Gradle); `npm run mobile:android:install` installs that APK and starts it, without compiling (`-- --serial <serial>` with several phones). Commands are per platform (`mobile:android:*`; iOS gets its own). By hand: `npm run mobile:android:sync`, then `cd apps/mobile/android && ./gradlew assembleDebug` with `ANDROID_HOME` set for the command only; install with `adb -s <serial> install -r`. Launcher icons: `npm run mobile:icons`. `android/local.properties` is git-ignored.
- **Device features** (position, picking a file) go through `src/platform-device.ts`, which falls back to the browser's geolocation and a file input; the catalogues (gear lists, star and deep-sky registries) load once through `src/catalogs.ts` (`catalogsReady()`), started after the first screen is shown.
- **Tests:** `apps/mobile/tests/*.test.ts` (Vitest; Ionic's elements are stubbed, see `tests/helpers.ts`). Type-check: `npm run typecheck:mobile`.
- **Alignment is structural, never a nudge.** Items line up because of their container (flex/grid `align-items`, `gap`, shared baselines, `margin-inline: auto`), with sizes and spacing from tokens or named CSS variables. No literal length in `top/left/right/bottom/inset/margin/padding/translate/vertical-align`, no fixed `height`/`line-height` faking a centring, no negative margin: it must stay aligned when the text wraps, the font scales or the language changes. An Ionic internal that misaligns is fixed through its CSS variables or parts, or by wrapping its content in a flex row.
- **Checks:** `node apps/mobile/scripts/check-no-nudges.mjs` (static, part of `npm run verify`) rejects pixel offsets in the app's CSS and styles. `npm run check:alignment` (the `check-alignment` skill; starts its own servers and browser, not in `verify`) measures the components page and the real screens at three sizes: baselines of text and chips, icons centred on rows, stacked edges, gaps, all within 0.5 px. It measures a build (`vite build --mode check`, served by `vite preview`), not the development server: the style sheets load in another order there, and a rule that weighs as much as one of Ionic's wins only in development. Measure layout in a build too; a rule overriding Ionic must outweigh its selector.
- **Skills:** `mobile-screen` (building a screen), `check-alignment` (measuring alignment) and `mobile-device-test` (testing on the real phone) in `.claude/skills/`.
